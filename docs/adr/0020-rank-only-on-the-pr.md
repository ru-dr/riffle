# 0020: Only the rank on the PR; everything else on the dashboard

- **Date:** 2026-11-09
- **Status:** Proposed
- **Owners:** #8 GitHub App, #12 Maintainer triage view (to confirm, see Open)

## Context

Under `contracts/org_config.schema.json` 5.0 the PR comment can carry the score (`pr_output.show_score`, off by default), the top SHAP factors (`pr_output.show_top_factors`, default 3) and mined evidence (`pr_output.evidence`, on by default). The proposal (`docs/project-proposal-v0.4.md`, section 3.2) also posts a rework brief on PRs predicted to need rework or go nowhere. On open-source repos that comment is read by the contributor. The narrator's reasons (`pipelines/narrator/reasons.py`) include facts about the author ("the author's earlier closed PRs here that went nowhere = 41 of 55"), the repo's recent handling and the predicted reason a PR will not merge ("likely abandoned by the author"), none of which suit a public comment. LLM narration (narrator layer 3) also needs settings the schema does not have (model name, API key, timeout), and `llm.endpoint` is not a locked key, so a repo file can change where features are sent.

## Decision

- **On GitHub, Riffle shows the rank only.** That is the band label, as today, and an optional comment with the PR's place in the queue and a link to its page on the dashboard. The rank comes from the active `ranking` mode (ADR 0019).
- **Never on a PR:** the score, any chance, the reasons, the narration, the evidence, or the predicted reason. This is fixed, not a setting.
- **Everything else is on the dashboard** (#12), visible to `dashboard.visibility` (default `repo_writers`). That includes the score now and at open, the three chances, the top reasons, the age line, the why-not-merging line, the comparison with the neighbouring PR, the evidence and the narration. The rework brief is shown there too.
- **The rank in the comment is refreshed when the PR is rescored, not on every queue change,** and the comment says when it was last updated. The dashboard is always current.
- **Narration rules, fixed rather than settings:**
  - The narrator only rephrases the reasons and evidence it is given.
  - Every number in LLM text must appear in that input, or the layer-1 text is shown instead.
  - Text is regenerated only when the reasons change.
  - After `llm.timeout_seconds` the layer-1 text is shown.
- **`/llm/endpoint` is added to the default `organization.locked_keys`.**
- **`contracts/org_config.schema.json` goes to 5.1, adding optional keys only:**

  ```yaml
  pr_output:
    rank_in_comment: position    # NEW: position | band | none (default: see Open)
    link_to_dashboard: true      # NEW
  dashboard:
    pr_page:                     # NEW: what the dashboard shows for one PR
      show_score: true
      show_chances: true
      show_top_factors: 4        # 0-7
      show_age_effect: true
      show_why_not_merging: true
      show_comparisons: true
      evidence: { cite_similar_prs: 3, failure_mode: true, scrutiny: true, path_size: true, release_cycle: true }
  llm:
    model: null                  # NEW: model name sent to the endpoint
    api_key_ref: null            # NEW, org only: name of the secret holding the key, never the key
    timeout_seconds: 8           # NEW: 1-60
  explanation:
    use_llm: true                # NEW: false = layer-1 text only, even when an LLM is set
  ```

- **Deprecated in 5.1, removed in 6.0:** `pr_output.show_score`, `pr_output.show_top_factors`, `pr_output.show_component` and `pr_output.evidence`. In 5.1 they are accepted, ignored on the PR, and one notice is posted; `evidence` moves to `dashboard.pr_page.evidence` with the same keys and defaults.
- **New code checks:**
  - `llm.provider` other than `none` requires `llm.endpoint`.
  - `llm.provider: hosted` requires `llm.api_key_ref`.
  - `llm.timeout_seconds` is between 1 and 60.
- **Files changed:** `contracts/org_config.schema.json`, `docs/contracts.md` (version history), `contracts/REFERENCE.md` (regenerated by `gen_reference.py`) and `fixtures/config/`.

## Options not taken

| Option | Why not |
| --- | --- |
| Keep 5.0 behaviour: top factors and evidence in the comment | Public on open-source repos; author history and predicted reasons are not for the contributor |
| Public rework brief on PRs predicted to need rework or go nowhere (proposal section 3.2) | Even without a score, a brief posted only on PRs predicted to fail tells the contributor the prediction; no privacy review of public comments (#13) has been done |
| Nothing on GitHub, dashboard only | Maintainers would have to open the dashboard to see any order; a label on the PR is the cheapest useful signal |
| Exact position always live in the comment | The position changes whenever any PR opens or closes and drifts daily with the age adjustment; editing that often runs into `limits.max_comments_per_hour` (120) |
| Narration in the comment, with LLM privacy settings only | The same privacy problem as the score, and an LLM text error would be public |

## Consequences

- **#8 GitHub App:** the comment template shrinks to the rank, the update time and a link. Labels are unchanged.
- **#12 Maintainer triage view:** becomes the only place for scores, reasons and narration, and needs a stable page URL per PR for the comment link.
- **#3 Rework brief:** the brief's reader changes from the contributor to the maintainer. Sections 3.2 and 4.4 of the proposal need updating, and so does any brief evaluation planned with contributors.
- **#9 Inference service:** the explainer serves one audience, the dashboard. `contracts/explain.schema.json` (not written yet) needs no public variant.
- **Contracts:** 5.1 is a minor bump, so every 5.0 file stays valid. 6.0 removes the deprecated keys.
- **Invariants:** no conflict.
  - The LLM stays off the scoring path: it writes text only, with a layer-1 fallback.
  - Nothing leaves the installation by default: `llm.provider: none` stays the default, and the endpoint is now locked.
  - Riffle still never blocks merges, and scores are unchanged.
- **The rank is still public.** A contributor can see that their PR is near the bottom (see Open).

## Revisit if

- Dashboard logs from the pilot or the Expo show that maintainers rarely follow the link from a PR to its dashboard page.
- A privacy review of public comments (#13) approves a contributor-facing brief.
- Rank refreshes on rescore exceed `limits.max_comments_per_hour` in a busy repo.

## Open

- **Default for `pr_output.rank_in_comment`:** `position` ("#3 of 41 open PRs in the review queue") or `band`. The position is more useful but changes often, and a low position is public.
- **Who sees the position:** every PR, or only the top N.
- **Posting the brief:** whether a maintainer can post the rework brief to the PR from the dashboard, as their own comment.
- **Owners:** #8 and #12 to confirm.
